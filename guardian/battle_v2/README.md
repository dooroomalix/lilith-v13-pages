# 마지막 성문의 수호자 · 전투 v4 (v4.0.0-build310)

v3는 **"캐릭터가 종이인형처럼 뚜벅뚜벅 움직인다"**는 지적을 프레임 수를 늘려 풀려 했지만,
프레임을 한 장씩 따로 생성해서 **프레임마다 카메라 배율·복장·몸 크기가 달라졌고**
(달리기 6프레임 중 4프레임이 공중 자세), 그림자도 접지도 없어 **"배경 위에 붙인 그림"**처럼 보였습니다.

v4는 사용자가 확정한 방향 —
**① 선명하고 화려한 애니/웹툰풍 ② 캐릭터·몬스터가 배경과 따로 노는 느낌 해소
③ 카엘·리아·보스 그림체 유지 ④ 1스테이지(폐허의 성문 + 아르카논) 출시 수준 완성도
⑤ 자연스러운 모델 워킹(걷기/달리기) 연구·개선** — 에 맞춰
**걷기/달리기 사이클을 새로 제작하고, 접지·조명·이펙트·배경 깊이·HUD를 전면 손봤습니다.**

- 대상 코드 `projects/guardian/battle_v2/` · 배포 `guardian/battle_v2/`
- 실행 `https://dooroomalix.github.io/lilith-v13-pages/guardian/battle_v2/`
- PixiJS v8.6.6 · 논리 좌표 1280×720 · DPR 최대 2배

## 1. 워킹(걷기/달리기) 연구 — 무엇을 근거로 고쳤나

애니메이션 런 사이클의 표준 키포즈와 게임 스프라이트 운용 수칙을 기준으로 삼았습니다.

| 구간 | 자세 | 몸 | 이 프로젝트에서의 처리 |
|---|---|---|---|
| **contact** | 앞발이 땅에 닿는 가장 넓은 자세, 뒷발은 막 떨어짐 | 가장 낮은 편 | 접지 프레임 → 먼지·그림자 스쿼시·발소리 |
| **down** | 앞 무릎이 체중을 받아 굽음 | 가장 낮음(무게) | bob +1.5%(아래로) |
| **push(break)** | 딛은 다리가 펴지며 밀어냄, 반대 무릎이 앞으로 | 상승 | bob −0.8% |
| **flight(peak)** | 두 발이 모두 땅에서 떨어짐 | 가장 높음 | bob −3.0%(위로) + 그림자 축소 |

- **8장이 표준**(contact/down/push/flight × 좌우 2스텝), 6장은 down을 빼서 만듭니다.
- 한 걸음은 **70~100ms**, 초당 **3~3.75걸음**이 자연스럽습니다. (6~8걸음/초는 "허둥대는" 느낌)
- contact는 가장 넓게, down은 가장 낮게, flight는 가장 높게 — **상하 움직임은 사인파가 아니라 계단 함수**입니다.
- 발이 땅을 박고 뒤로 가는 속도 ÷ 프레임 시간 = 캐릭터 이동 속도여야 **발이 미끄러지지 않습니다.**
  → v4는 애니메이션을 시간이 아니라 **이동 거리로** 돌립니다(§2-2).
- 참고: Adobe 「Run Cycle Guide」, AnimSchool 「The Key Poses of a Run Cycle」, 픽셀아트 규칙
  「Walk and run」(contact/down/pass/up, 8-frame ladder, foot-slide 규칙).

## 2. 카엘 스프라이트 재제작

### 2-1. 한 장에 여러 포즈를 그려 자르는 방식 (프레임 편차 제거)

프레임을 1장씩 생성하면 배율과 복장이 달라집니다. v4는 **한 이미지에 3~4포즈를 나란히 그린 스트립**을
생성한 뒤 잘라 씁니다. 같은 이미지 안의 포즈는 배율·카메라·복장이 거의 같습니다.

- 새 시트: **달리기 8프레임**(contact/down/push/flight ×2), **걷기 6프레임**(contact/down/passing ×2),
  **대기 4프레임**(호흡) — 기존 3프레임 대기 중 1프레임이 정면이라 측면 달리기와 충돌하던 문제도 해결
- 파이프라인 `tools/anim_prep_v4.py`
  1. 마젠타 배경 → 알파 매팅(언프리멀티플라이 + despill + 1px 침식)
  2. 가로 스트립을 **빈 열(또는 열 밀도 골짜기)로 피규어 분리**, 이웃 피규어의 검끝/망토 조각은 연결요소 분석으로 제거
  3. **발 기준선 검출**: 검의 시안/청색 광을 제외하고, 폭 26px 이상의 덩어리가 있는 가장 낮은 행 = 디딘 발
  4. **스트립 단위 정규화** — 스트립마다 그려진 배율이 달라서, 스트립별 중간값으로 `BODY_H=410px`에 맞춤
  5. 모든 프레임의 발을 같은 기준선에 앉히고 가로축은 몸통 무게중심에 정렬 → 시트 + `meta.json`
     (`frameW/H`, `anchorX/Y`, `pxBodyH`, `bob`, `contacts`)
- 저장은 0.85배 해상도(WebP, 알파) — 달리기 시트 242KB

### 2-2. 이동 거리 기반 사이클 (발 미끄러짐 제거)

```js
// actors.js — _advanceCycle()
const fps = clamp(n * (거리/dt) / cycleDist, 3.4, 24);   // cycleDist: 달리기 172px, 걷기 116px
this.cycle += (fps * dt) / n;
```
- **한 사이클 = 실제로 이동한 172px(달리기)/116px(걷기)** → 속도가 변해도 발이 같은 속도로 뒤로 갑니다.
- 260px/s에서 초당 약 3.0걸음, 110px/s에서는 걷기 사이클로 자연스럽게 전환(속도 150px/s 기준).
- 프레임 인덱스가 **contact 프레임을 지날 때마다** 발소리·먼지·그림자 스쿼시를 발생시킵니다.

### 2-3. 땅에 붙어 있다는 느낌 (접지 연출)

| 요소 | 내용 |
|---|---|
| 접지 그림자 | 소프트 타원. 뜨는 프레임에서는 넓고 흐리게, 딛는 순간 좁고 진하게(스쿼시) |
| 발밑 환경광 | 가산 타원이 바닥을 물들여 캐릭터 빛이 땅에 반사되는 느낌 |
| 림라이트 | 같은 프레임을 6px 어긋나게 뒤에 깔아 가장자리만 시안으로 빛나게 |
| 먼지/광입자 | contact마다 발치 먼지 + 작은 빛 입자, 가속 중에는 속도선 |
| 원근 배율 | y(깊이)에 따라 0.96~1.04배로 미세 조정, 그림자 크기도 함께 |
| 방향 전환 | 반대로 꺾을 때 먼지 + 기울기 전환(가속·감속 lerp) |

## 3. 캐릭터·배경 융합과 배경 입체감

- **레이어 분리**: 하늘(성문·빛줄기) / 원경 안개 / 바닥·바닥안개 / **캐릭터** / 이펙트 / **전경 안개·근경 입자**
- **성문 빛줄기 4겹**: 회전·폭·밝기를 서로 다른 주기로 흔들어 "멈춘 그림 1장" 느낌 제거
- **바닥 안개 3겹 + 전경 안개 2겹**: 발등 높이 안개로 캐릭터가 바닥에 잠기고, 전경 안개가 캐릭터 앞을 지나 깊이를 만듦
- **부유 입자**: 빛줄기 속 먼지 26개(뒤) + 큰 먼지 10개(앞), 불티 40개
- **카메라**: 시차(레이어별 0.10~0.85), 줌·셰이크를 월드 단위로 적용, 캐릭터 위치에 따라 초점 이동

## 4. 애니/웹툰풍 이펙트

- **2색 검기**: 바깥 잔광 → 시안 → 골드/백색 테두리 → 백색 코어 (3타는 골드 테두리)
- **블레이드 트레일 4겹** + 선두 섬광, 칼끝 잔검 파편
- **네 갈래 별 섬광**(`spark` 텍스처) + 방향성 스파크 + 방사 버스트
- **다중 충격파 링**(가로로 눌린 타원 + 지면 할로) → 3타·보스 강타·궁극기
- **파편(debris)**: 바닥 충격 시 회전하는 조각
- **속도선**: 대시·고속 이동·퍼펙트 카운터
- **크리티컬**: 골드 섬광 + "CRITICAL" 팝 + 히트스톱 1.25배 + 화면 플래시
- **퍼펙트 카운터**: 줌·슬로우·충격파 3겹·좌우 속도선·골드 버스트

## 5. HUD

- 모서리를 자른 판타지 패널 + 골드 테두리 + 다이아 장식, 초상화 프레임 글로우
- **HP**: 그라데이션 + 광택 + **피해 잔상 게이지**(늦게 따라오는 붉은 바) + 6분할 눈금 + 저체력 경고 펄스
- **MP**: 흐르는 빛 스윕
- **쿨다운**: 부채꼴 스윕 + 남은 초
- **보스 HP**: 장식 단부·다이아·10분할 눈금·잔상 게이지, 이름/수치
- **콤보**: 크기 변화 + 골드, 20콤보 이상 색 변화
- 일시정지/결과 오버레이도 같은 판타지 프레임으로 통일

## 8. 알려진 한계

- 프레임은 이미지 생성 모델로 뽑아 **프레임 간 복장 장식이 미세하게 다릅니다**(배율·발 기준선·몸 축은 정규화).
  완전히 동일한 모델링이 필요하면 3D 리깅/스파인으로 교체해야 합니다.
- 발 기준선은 휴리스틱(검광 제외 + 폭 26px 덩어리)으로 찾습니다. 포즈가 크게 달라지면
  `tools/anim_prep_v4.py`의 임계값(26px)을 조정해야 할 수 있습니다.
- 헤드리스(소프트웨어 렌더) 환경에서는 실제 프레임레이트를 측정할 수 없어,
  모바일 GPU 60fps 확인은 실기기 테스트가 필요합니다.
