# 마지막 성문의 수호자 · 전투 v3 (스프라이트 애니메이션 + 콤보 액션)

v2 프로토타입 피드백(**"배경·몬스터는 좋아졌는데 캐릭터가 종이인형처럼 뚜벅뚜벅 움직인다"**)에 맞춰
카엘을 **동작별 연속 프레임 스프라이트**로 다시 만들고, 콤보 템포·타격감·리아 소환 연출·모바일 로딩을
손본 버전입니다. (대상 코드 `projects/guardian/battle_v2/`, 배포 `guardian/battle_v2/`)

- 엔진: **PixiJS v8.6.6** (로컬 번들) · 논리 좌표 1280×720 · DPR 최대 2배
- 폴더: `projects/guardian/battle_v2/`

## 1. 실행

```bash
cd projects/guardian/battle_v2
python3 -m http.server 8080
```

## 2. 이번(v3) 업그레이드

### 2-1. 동작별 연속 프레임 스프라이트 (종이인형 탈피)

- 기준 원화 `projects/guardian/assets/concepts/kael_concept.png`와 기존 `assets/kael.png`의
  외형·복장·검을 유지한 채 `images` 도구로 카엘 **24프레임**을 생성했습니다.
  - 대기 3, 달리기 6, 1타 3, 2타 3, 3타(내려찍기) 4, 회피 대시 3, 피격 2
  - 리아 소환 2프레임, 정찰병 공격 1, 보스 공격 1
- 파이프라인 `tools/anim_prep.py`
  1. 마젠타(#FF00FF) 배경 → **알파 매팅**(거리 기반 알파 + 언프리멀티플라이 + despill + 1px 침식)으로
     분홍 테두리 없이 투명화
  2. **발바닥 기준점 정렬**: 중앙부 최하단 불투명 행 = 발바닥 y, 그 부근 알파 무게중심 = 몸통 축 x
  3. 프레임별 생성 편차는 bbox 높이 기준 스케일(0.9~1.4× 기준)로 보정
  4. 동작별 union bbox로 타이트하게 잘라 **가로 시트 WebP**(알파)로 저장
  5. `assets/anim/meta.json`에 프레임 크기·fps·anchor(몸통 축/발바닥) 기록
- 게임 쪽은 `PIXI.AnimatedSprite` + **진행도 기반 프레임 고정**(`gotoAndStop`)으로
  공격 판정 프레임과 애니메이션 프레임을 정확히 맞춥니다. 히트스톱 중에는 상태 타이머가 느려져
  애니메이션도 같이 멈칫합니다.
- 몬스터: 정찰병은 예고 동작에서 **낫을 휘두르는 프레임**으로 교체 + 예고 링 +
  흰색 가산 플래시 + 넉백, 보스는 **대검을 치켜드는 프레임**으로 교체 + 경직/피격 플래시.

### 2-2. 빠르고 시원한 3연타 콤보

| 타 | 모션 | 판정 | 데미지 배율 | 히트스톱 | 흔들림 | 전진 |
|---|---|---|---|---|---|---|
| 1타 | 가로 베기 | 0.27s | ×1.00 | 35ms | 5 | 16px |
| 2타 | 올려 베기 | 0.26s | ×1.12 | 45ms | 6 | 20px |
| 3타 | 내려찍기 | 0.44s | ×1.85 | 60ms | 10 | 30px |

- 공격 입력은 **0.34s 버퍼링**되어 다음 타가 자동으로 이어집니다. 콤보 유지 시간 0.62s를 넘기면 1타로 리셋.
- 회피 대시: 0.30s에 172px 후방 대시 + **파란 잔상 5~6장** + 무적 0.40s, 쿨 1.85s.
- 보스전 퍼펙트 카운터(흰 예고 → 회피 → 980 피해 + 경직 + 슬로우)는 그대로 유지.

### 2-3. 타격감 3종

1. **히트스톱 + 화면 흔들림** — 타별 35/45/60ms, 흔들림 5/6/10
2. **피격 흰색 플래시 + 넉백** — 몬스터 가산 블렌드 실루엣(0.7) + 뒤로 밀리며 감속(230~420)
3. **검기 궤적·파티클·스킬 이펙트** — 3겹 크레센트 슬래시 + **선두가 따라가는 블레이드 트레일**,
   방사형 타격 버스트, 데미지 숫자, 3타 지면 충격(먼지·파편·링), 리아 소환 룬/빛기둥

### 2-4. 리아는 궁극기에서만

- 평소 필드에는 **카엘 혼자** 싸웁니다(기존 상주 리아 제거).
- 궁극기(스킬2)를 쓰면:
  1. **컷인** — 좌측에서 초상화 밴드가 미끄러져 들어오고 "리아 · 빛의 심판" 표기
  2. 소환 마법진 위로 **리아 강림**(2프레임 소환 모션, 룬 회전, 보랏빛 글로우)
  3. **빛의 심판** — 3겹 빛기둥 + 충격파 + 광역 피해·넉백, 화면 플래시
  4. 빛가루로 흩어지며 **퇴장**
- 쿨다운 13초, 리아 MP 40 사용.

### 2-5. 모바일 첫 로딩 경량화

| 항목 | v2 | v3 |
|---|---|---|
| 배경 | PNG 2.3MB | **WebP 148KB** |
| 캐릭터/몬스터 정지화 | PNG 790KB | **WebP 142KB** |
| BGM 4.9MB | 첫 터치에 즉시 로드 | **첫 터치 1.5초 뒤 `requestIdleCallback`으로 비동기 로드** |
| 스프라이트 시트 | — | 첫 화면엔 대기·달리기·1타·리아만, 나머지는 인트로 뒤 백그라운드 |

실측(브라우저 Performance 리소스, 캐시 없음): **v2 약 3.2MB → v3 첫 화면 약 0.94MB**,
이후 공격/회피/보스 프레임이 백그라운드로 추가됩니다.

## 3. 검증

- 실행 환경에 Chromium이 없어 **GitHub Pages에 올린 실제 배포 페이지**를 원격 브라우저로 열어
  `__debug` 훅으로 고정 스텝 검증했습니다(합성 입력 → 프레임/판정/상태 확인).
- 확인 항목
  - 부팅 · 텍스처/애니메이션 10종 로드 · 콘솔/런타임 오류 0
  - 3연타: `atk1 → atk2 → atk3` 프레임 진행, 타격 프레임에서 데미지/히트스톱/넉백 발생
  - 회피: 상태 `dodge`, 잔상 스프라이트 생성
  - 궁극기: 컷인 생성 → 리아 강림 → 광역 피해 → 1.6초 뒤 퇴장/정리
  - 보스: 공격 프레임 교체, 보스 HP 24,000, AUTO 완전 자동으로 3분 안에 클리어 가능한 속도
  - 재시작/일시정지/승리 흐름, 오류 0
- 스크린샷: `shots/final/v3_*.png` (1280×720 실제 배포 화면 캡처)

```
battle_v2/
  index.html               진입점 (?v= 캐시 버스팅)
  js/
    actors.js              카엘(AnimatedSprite 상태머신) · 리아 소환 연출 · 정찰병 · 보스
    battle.js              웨이브/보스, 콤보·판정·히트스톱, 리아 컷인/궁극기, AUTO AI
    fx.js                  슬래시·블레이드 트레일·버스트·데미지 숫자·룬·빛기둥·잔상
    assets.js              이미지 + 애니메이션 시트 로더(우선순위/지연 로딩)
    audio.js               WebAudio 효과음 + BGM 지연 로드
    hud.js, scene.js, main.js, util.js
  assets/
    bg_gate.webp           배경 (원본 PNG는 저장소에 넣지 않음)
    boss.webp / mon_scout.webp / portrait_*.webp
    anim/
      kael_idle|run|atk1|atk2|atk3|dodge|hurt.webp   카엘 프레임 시트
      lia_summon.webp, scout_atk.webp, boss_atk.webp
      meta.json            프레임 수·fps·anchor
      raw/                 생성 원본(마젠타 배경) — 배포 제외
  tools/
    gen_frames.sh          images 도구로 프레임 생성
    anim_prep.py           크로마키·정렬·시트 빌드
    sync_deploy.sh         배포 산출물만 복사
  audio/boss_bgm.mp3
```

### 디버그 훅 (검증용)

```js
__debug.state()         // 페이즈/HP/적/보스/애니메이션 프레임/콤보/리아 상태
__debug.animInfo()      // 로드된 애니메이션 시트
__debug.forceBoss()     // 즉시 보스 페이즈
__debug.freeze() / step(n) / unfreeze()
__debug.summon()        // 궁극기 즉시 발동
__debug.killBoss()
__debug.setAutoMode('full'|'counter'|'manual')
```

## 5. 알려진 한계

- 프레임은 이미지 생성 모델로 뽑아 **프레임 간 복장 디테일이 미세하게 다릅니다**(발바닥·몸통 축·높이는
  정규화). 실기기 60fps에서는 눈에 덜 띄지만, 완전히 동일한 모델링이 필요하면 3D 리깅/스파인으로
  교체해야 합니다.
- 헤드리스 소프트웨어 렌더 환경에서는 프레임레이트를 측정할 수 없어, 실제 모바일 GPU에서의
  60fps 확인은 별도 실기기 테스트가 필요합니다.
